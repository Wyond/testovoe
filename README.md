# waap-matcher

Матчинг 1 114 166 HTTP-запросов против всех 12 172 правил `nmap-service-probes` на Go. Для каждого запроса — список сервисов, раздельно `match` и `softmatch`, в порядке приоритета. История решений и все замеры — в `docs/DECISIONS.md`, `docs/EXPERIMENTS.md`, `docs/INTERVIEW.md`.

## Результат

Apple M4 (4 производительных + 6 энергоэффективных ядер), 24 ГБ, Go 1.27.2. Медиана трёх прогонов, весь корпус, результат пишется в файл.

Основная конфигурация — **гибрид + PCRE2**: все 12 172 правила; каждое подтверждается тем движком (Go, RE2 или Rust regex), который оказался быстрее на калибровке; 807 правил, которые Go не компилирует, идут через PCRE2.

- **Чистый Go без внешних зависимостей**, в том же прогоне: 11 365 правил; 8.85 с на одном воркере, 1.84 с (607 тыс. req/s) на десяти.
- **Полный прогон:** конвертация JSON в бинарный корпус 10.8 с (однократно) + подготовка правил 0.22 с + матчинг 1.43 с = **12.5 с**.
- **Baseline:** наивный однопоточный проход тех же правил тем же движками, 100 000 запросов — 499.8 с (200 req/s). Быстрый режим на тех же запросах — 1.04 с, **в 480 раз быстрее**. Разброс быстрого режима 0.71–1.56 с, это шум машины.
- **Корректность:** на этих 100 000 запросах вывод наивного и быстрого режима побайтно совпал. 1 воркер и 10 воркеров дают одинаковый результат на всём корпусе. Тесты проходят на каждом движке.
- **Покрытие:** PCRE2 возвращает все 807 правил, которые Go не компилирует. На корпусе это добавляет совпадения в 611 запросах, все от одного правила длины (`landesk-rc`). Ни одно прежнее совпадение не пропало.

Вывод `results/out.jsonl` — по строке на запрос, включая пустые: `{"id":4,"hard":["pc-duo","ventrilo"],"soft":[]}`. Приоритет — порядок Probe в файле, затем строк.

## Как получить числа

```bash
scripts/run.sh                                         # скачает данные в data/, если их нет
LEGIT=/path/Legitimate MAL=/path/Malicious scripts/run.sh
```

- **Зависимости гибрида:** `brew install re2 pcre2 pkg-config rust`. Rust-библиотеку скрипт собирает сам.
- **Без зависимостей** скрипт меряет только чистый Go.
- **Время:** около 20 минут, из них 8 — наивный baseline.
- **Результаты:** `results/summary.md`, сырые метрики — `results/metrics.jsonl`.
- **Воспроизводимость:** проверена из пустой папки (`git clone` → скачивание → прогон). Файл правил закреплён на коммите nmap `3b71f80`.

## Как устроено

1. **Подготовка корпуса.** JSON → `corpus.bin` (запросы подряд) + `corpus.idx` (смещения) + манифест. Разбор на `jx` без аллокаций строк. Нормализация: `METHOD URL HTTP/1.1`, заголовки в исходном порядке, тело целиком, без декодирования.
2. **Предфильтр.** Из синтаксического дерева каждого правила выводится условие, без которого совпадения быть не может: литеральный префикс, обязательный литерал, границы длины, первый и последний байт. Литералы ищутся одним проходом по запросу через Bloom-фильтр по 3-граммам. Остаётся **13.7 вызова regex на запрос вместо 12 172**.
3. **Подтверждение.** Движок для каждого правила выбирает `matcher calibrate` по измеренному времени на отдельной выборке. 13 правил ушли на RE2 или Rust regex — это даёт ~25–30% к скорости.
4. **Воркеры.** Общий атомарный счётчик раздаёт диапазоны по 256 запросов. Запросы читаются из mmap, всё изменяемое — у воркера; 0 аллокаций на запрос.

## Несовместимые паттерны

- **Уровень 1 — честный учёт.** Go не компилирует 807 правил: negative lookahead 670, атомарные группы 79, possessive 26, обратные ссылки 16, lookahead 13, lookbehind 2, повтор >1000 — 1. Без PCRE2 они исключаются, и это печатается при каждом запуске.
- **Уровень 2 — возврат через PCRE2.** Для предфильтра правило ослабляется: lookaround выбрасываются, обратная ссылка становится `.*`. Язык ослабленной формы шире исходного, поэтому фильтр не теряет совпадения. Перебор ограничен лимитами исполнения, а их срабатывание считается отдельно, а не как «нет совпадения». JIT выключен: в PCRE2 10.49 он читает за концом входа, оканчивающегося невалидным UTF-8. Это нашёл тест.
- **Уровень 3 — семантика.** Скомпилированное — ещё не «как в nmap». Все движки работают по символам UTF-8, nmap — по байтам: `\xff` у нас — символ ÿ, `$` — только конец текста. Сверки с PCRE в байтовом режиме не было.

## Что пробовал и что отбросил

- **Поиск литералов:** `bytes.Contains` на каждый литерал (276 проходов) и литералы из 2–3 обычных байт съедали больше половины времени. Заменены одним проходом.
- **Регистронезависимые литералы:** без них три правила давали 90% времени regex. Ускорение после добавления — в 8 раз.
- **Конвертация:** `encoding/json` → `jx`: аллокаций в 4 раза меньше, 14 → 10 с. Окно конвертера «N файлов вперёд» заменено лимитом байт.
- **Целиком другой движок вместо Go:** RE2 медленнее в 1.7–1.8 раза, Rust вровень, PCRE2 в 10 раз медленнее. Без предфильтра RE2 был бы в 2.5 раза быстрее Go, но предфильтр уже убрал ту работу, где он выигрывает. Отсюда гибрид.
- **`pread` вместо mmap, `madvise`, размер батча 16…4096** — эффекта нет.
- **Не пробовал:** Hyperscan, Aho–Corasick из библиотеки, regexp2.

## Где упёрся

- **Матчинг.** После предфильтра профиль приписывает основное время первому обращению к байтам запроса, а не regex. Замена mmap на `pread` даёт то же время. Счётчиков кэша на macOS нет, так что «упёрлись в доставку данных из памяти» — гипотеза.
- **Тяжёлый хвост.** 0.03% запросов больше 1 МБ — это загрузки файлов, раздутые датасетом в 1.8 раза: невалидные байты записаны как `�`. На них приходится 22% байт корпуса.
- **Полный прогон** упирается в конвертацию: она грузит ~1.3 ядра, потому что самый большой JSON-файл разбирается одним потоком, а запись идёт по порядку.
- **Линейность.** После 4 ядер эффективность падает. Однотипных ядер у M4 только 4, к тому же это MacBook Air без вентилятора: под долгой нагрузкой те же прогоны бывают медленнее на 40–50%.

## 100M / 1B

- **Корпус и индекс.** 1B запросов — 8 ГБ одних смещений и терабайты данных; mmap не помещается в page cache. Нужны сегменты со своими индексами.
- **Конвертация.** Уже сейчас она дольше матчинга. Её надо делать по сегментам, параллельно и с большими файлами первыми — или читать данные без JSON.
- **Сбои.** Счётчик `Add` — захват диапазона, а не подтверждение. Нужен checkpoint с watermark (конец непрерывно завершённого префикса) и идемпотентный вывод.
- **Несколько машин.** Шард = часть корпуса со своим курсором и watermark, балансировка по байтам, а не по числу запросов.
- **Вывод.** `ventrilo` совпадает почти со всеми запросами — на 1B такие правила надо агрегировать.
